# GlossCheck — AI-чат для бизнеса с управлением без программиста

**Клиент получает AI-сервис, которым может управлять самостоятельно.** Логику обработки сообщений, ответы модели и ограничения использования можно настроить из привычной административной панели WordPress — без правок PHP или JavaScript.

GlossCheck — пример индивидуальной разработки AI-чата на **WordPress + DeepSeek API**. Вместо универсального чат-виджета создан собственный плагин с историей диалогов, настройками модели, управлением доступом и контролем расходов.

> **Статус демонстрации:** исходный код и описание доступны в этом публичном репозитории. Рабочий клиентский домен сейчас недоступен, поэтому ссылка на него не используется как действующее демо.

## Что решает для заказчика

- Даёт посетителю возможность общаться с AI через интерфейс сайта.
- Сохраняет историю диалогов в базе WordPress.
- Поддерживает гостевые обращения и сценарии для авторизованных пользователей.
- Позволяет администратору управлять поведением чат-ассистента без привлечения разработчика.
- Помогает контролировать расходы на LLM API за счёт лимитов истории, длины ответа и частоты сообщений.
- Не привязывает бизнес-логику к стороннему конструктору ботов: серверная часть находится в собственном WordPress-плагине.

## Что заказчик меняет самостоятельно

В административной панели WordPress доступны разделы **«Настройки чата»**, **«История чатов»** и **«Пользователи чата»**.

| Возможность | Что меняется без программирования |
| --- | --- |
| Инструкции для AI | Системный промпт для новых диалогов: роль ассистента, тон общения и правила ответов |
| Модель | Название используемой модели DeepSeek |
| История контекста | Максимальное число сообщений, передаваемых в диалог |
| Размер ответа | Лимит токенов ответа модели |
| Частота обращений | Лимит сообщений в минуту на посетителя |
| Контроль работы | Просмотр истории чатов и пользователей, настройка отдельных пользовательских лимитов |

**Важная деталь:** обновлённый системный промпт применяется к новым диалогам; начатые диалоги сохраняют прежнюю версию инструкций. Это предотвращает неожиданное изменение поведения уже открытого чата.

### Что не является конструктором

Это **AI-чат с админкой**, а не визуальный редактор произвольных деревьев кнопок, рассылок и веток Telegram-бота. Изменение архитектуры, новых интеграций и нестандартной логики потребует разработки. Для сценариев, где клиент должен сам собирать блок-схемы, нужна отдельная CMS/конструктор или специальный визуальный редактор.

## Как устроено решение

```text
Посетитель сайта
   ↓
Интерфейс WordPress
   ↓
Собственный плагин GlossCheck DeepSeek Chat
   ├─ настройки и системный промпт
   ├─ история и доступ пользователей
   ├─ ограничения частоты запросов и токенов
   └─ запросы к DeepSeek API
          ↓
       Ответ AI
```

**Технологии:** WordPress, PHP, JavaScript, AJAX, DeepSeek API, база данных WordPress, кастомная тема оформления. Для локального ознакомления есть Docker Compose.

Публичный срез кода показывает именно **текстовый AI-чат и управление им через WordPress**. Функции OCR и обработки вложений описаны в отдельном портфолио проекта, но в текущих исходниках этого репозитория не подтверждены — поэтому они не заявляются здесь как готовая возможность публичной версии.

## Моя роль

Проектирование сценария, создание интерфейса и собственного WordPress-плагина, интеграция DeepSeek API, административная часть, ограничения использования и запуск клиентского решения.

## Для похожих проектов

Такой подход подходит, когда нужен AI-ассистент с самостоятельным управлением со стороны заказчика, а стандартный конструктор ограничивает логику интеграций или контроль над сервисом.

**Что можно обсудить:** источники ответов, админку для бизнес-пользователей, интеграцию с CRM, Telegram или сайтом, требования к данным и ожидаемую нагрузку. Возможности сверх показанных в репозитории оцениваются отдельно.
